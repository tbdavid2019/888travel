# ai-copilot Specification

## Purpose
Provides an in-app conversational AI travel assistant enabling travelers to discuss trip plans, explore recommendations, and review structured proposal cards for one-click timeline integration.

## Requirements

### Requirement: Backend AI Chat Gateway
The system SHALL provide an authenticated `POST /ai/chat` endpoint that routes user messages and travel context to the user's configured LLM provider (Groq, Gemini, DeepSeek, OpenAI, Anthropic, or custom), resolving tenant-specific BYOK credentials when available and falling back to host defaults for admin.

#### Scenario: Authenticated chat request with trip context
- **WHEN** an authenticated user sends `POST /ai/chat` with message history and active trip details
- **THEN** the system SHALL invoke the configured LLM with travel hub system instructions and return the assistant response containing conversational text and optional structured proposals

#### Scenario: Sliced Trip Context Injection
- **WHEN** an authenticated user invokes `POST /ai/chat` with `currentTripId`
- **THEN** the system SHALL serialize active trip metadata and a minified segment list (`[start] type: name (note)`), excluding internal identifiers and bulky metadata to preserve model token limits

#### Scenario: Global Context Fallback
- **WHEN** an authenticated user invokes `POST /ai/chat` without `currentTripId`
- **THEN** the system SHALL provide a concise summary of upcoming trips (ID, Destination, Dates) to the assistant instructions

#### Scenario: Tenant BYOK Key Resolution
- **WHEN** an authenticated tenant calls `POST /ai/chat` and has a BYOK configuration in `user:<uid>:llm_config`
- **THEN** the system SHALL route the request using the tenant's personal API credentials

#### Scenario: Unconfigured LLM provider returns descriptive guidance
- **WHEN** a user invokes `POST /ai/chat` before configuring an LLM API key in Settings and no host fallback is granted
- **THEN** the system SHALL return HTTP 400 with error code `NO_LLM_KEY` instructing the user to configure an LLM key in Settings

### Requirement: In-App Copilot Interface
The system SHALL provide a responsive, conversational chat drawer accessible via global navigation and individual trip card action menus.

#### Scenario: Open Copilot from global navigation
- **WHEN** user clicks the `✨ AI 助理` button in the top navigation bar
- **THEN** the system SHALL open the Copilot drawer and display recent conversation or welcome quick prompt chips

#### Scenario: Open Copilot with trip context
- **WHEN** user clicks `✨ AI 規劃此旅程` on a specific trip card
- **THEN** the system SHALL open the Copilot drawer, bind the active trip ID and its segments into the conversation context, and prompt the user for trip-specific adjustments

### Requirement: Structured Action Proposals
The system SHALL instruct the LLM to format itinerary modifications into structured action blocks containing valid segment data and optional fallback alternatives.

#### Scenario: Assistant proposes new segments
- **WHEN** the user asks the assistant to plan or recommend activities, flights, hotels, or restaurants
- **THEN** the assistant response SHALL include structured proposals conforming to the 7 travel categories (`flight`, `hotel`, `restaurant`, `car`, `ride`, `rail`, `other`)

#### Scenario: Assistant proposes fallback alternatives
- **WHEN** proposing dining or weather-sensitive attractions
- **THEN** the assistant response SHALL include a viable backup venue in the `fallback` proposal property

### Requirement: Interactive Preview and One-Click Execution
The system SHALL render interactive preview cards for all structured proposals inside the chat stream, allowing the user to review before applying changes.

#### Scenario: User applies proposed itinerary item
- **WHEN** user clicks "✓ 確認套用至行程 (Apply to Itinerary)" on a proposal card
- **THEN** the system SHALL persist the new segment into the trip in KV and immediately update the timeline view

#### Scenario: User dismisses proposal card
- **WHEN** user clicks "✕ 忽略 (Dismiss)" on a proposal card
- **THEN** the card SHALL transition to a dismissed state without altering any trip data

#### Scenario: XSS and HTML Sanitization
- **WHEN** rendering conversational text and proposal action cards
- **THEN** all LLM-supplied strings SHALL be HTML-escaped with `esc()` before insertion into the DOM, and external URLs SHALL be validated for HTTPS protocol and safe target attributes

### Requirement: Manual Invariant Protection for Copilot Actions
The system SHALL assign `source: "manual"` to all trips and segments created or updated through the AI Copilot.

#### Scenario: Preserving AI created plans against background sync
- **WHEN** an itinerary item generated by the AI Copilot is applied to a trip
- **THEN** its source property SHALL be set to "manual", ensuring background calendar and email syncs never overwrite or delete it
