# Design

## Context
RoamRadar is a single-tenant personal travel hub running on Cloudflare Workers and Cloudflare KV (`env.TRIPS`), with a pure Vanilla HTML5/CSS/JS frontend served from Workers static assets. Currently, the API (`/trips`, `/sync`, `/settings`) is tailored to browser session cookies (`travel_auth`) or header tokens (`X-Auth`) validated against a hashed password in KV. External LLMs require a standardized, stateless Bearer token mechanism, RESTful granularity (creating/updating individual segments), machine-readable discovery (`llms.txt`), and a portable agent skill definition (`SKILL.md`).

## Goals / Non-Goals

**Goals:**
- Provide a clean, versioned REST API (`/api/v1/trips` and `/api/v1/trips/:id/segments`) with standard HTTP verbs and status codes.
- Implement stateless Bearer token authentication with dedicated API keys (`rr_agent_...`) managed directly in Settings.
- Support full CRUD for all 7 travel categories (`flight`, `hotel`, `restaurant`, `car`, `ride`, `rail`, `other`) and structured fallback plans (`fallback`).
- Serve `/llms.txt` and `/llms-full.txt` at the root domain following the standard LLM manifest spec.
- Serve `/skill.md` and embed a copyable Agent Skill and System Prompt directly in the Settings modal.
- Maintain the strict invariant: all segments ingested through the Agent API are marked `source: "manual"`, protecting them against automated overwrite or deletion during background syncs.

**Non-Goals:**
- Multi-tenant OAuth2 flows or granular permission scopes (single-tenant architecture means the agent acts with full user delegation).
- Rate-limiting infrastructure beyond Cloudflare's built-in DDoS/WAF protections.
- Client SDK generation (the API is pure JSON HTTP, designed for native LLM tool use).

## Decisions

### Decision 1: Dedicated Agent API Key (`rr_agent_...`) vs Reusing User Password
- **Choice**: Generate cryptographically random tokens prefixed with `rr_agent_` stored in KV under `agent_api_key`.
- **Rationale**: External agents and LLMs should never hold the user's root account password. A separate agent token can be revoked and regenerated at any time from Settings without logging the user out of their browser sessions.
- **Alternative considered**: HTTP Basic Auth with account password (rejected for security reasons).

### Decision 2: Granular Segment Endpoints vs Whole-Trip Replacements
- **Choice**: Provide `/api/v1/trips/:id/segments` (POST, PUT, DELETE) in addition to `/api/v1/trips` (GET, POST, PUT, DELETE).
- **Rationale**: LLM agents commonly execute atomic actions (e.g. "Add a reservation at Tokyo Tower on Oct 16th", "Update seat number on flight"). Requiring the LLM to fetch, parse, and upload the entire 20-item trip array increases token usage, latency, and race-condition risk.
- **Alternative considered**: Only whole-trip upserts (rejected due to excessive LLM context and hallucination risk).

### Decision 3: Standard `llms.txt` and `SKILL.md` Serving Strategy
- **Choice**:
  1. Serve `/llms.txt` and `/llms-full.txt` directly via the Cloudflare Worker.
  2. Serve `/skill.md` directly via the Worker.
  3. In the Settings UI, provide a dedicated "AI Agent Integration" section with:
     - API Key generation & display
     - One-click copy for tailored Agent System Prompt
     - One-click copy / download for `SKILL.md`
- **Rationale**: Agents browsing via URLs can read `/llms.txt`, while humans setting up Claude Projects, ChatGPT Custom GPTs, or Codex/Antigravity skills can copy or download the pre-configured `SKILL.md` instantly.

## Risks / Trade-offs

- **[Risk: Malformed category or dates generated by LLM]** → *Mitigation: Validate `type` against `["flight", "hotel", "restaurant", "car", "ride", "rail", "other"]` (fallback to `other`), and normalize ISO date strings (`YYYY-MM-DD` or `YYYY-MM-DDTHH:mm`).*
- **[Risk: Accidental overwriting of manual user itinerary items]** → *Mitigation: Every segment created by the Agent API is stamped with `source: "manual"`, preventing background calendar and email ingestion syncs from touching it.*
- **[Risk: Leaked agent token]** → *Mitigation: The Settings UI provides an immediate "撤銷並重新產生 (Revoke & Regenerate)" action that invalidates the old token in KV instantaneously.*

## Migration & Rollout Plan
1. Zero breaking changes: Existing `/trips`, `/settings`, and web UI endpoints remain 100% untouched.
2. Deploy Worker update with `/api/v1/*`, `/llms.txt`, and `/skill.md`.
3. Update `travel-app.html` Settings modal and mirror to `public/app.html`.
4. Deploy to live instance and verify via curl.
